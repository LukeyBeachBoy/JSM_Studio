## Inheritance-safe choices

Choosing a card or a preset that is the default used to delete the line. In a configuration that includes a base, or one edited for a single controller (Layout's `# @controller type-N` lines), deleting the line hands the base's value straight back, so "Moving" or "Even" did nothing. Fixed, without touching the shared writers' meaning of "Use Default":

- A card that is a default **mode** writes the name: `RIGHT_STICK_MODE = NO_MOUSE`, `ZL_MODE = NO_FULL` (`SticksPage` no longer maps NO_MOUSE to ''; `useStickConfig` keeps a named NO_FULL).
- A **preset** that equals the default goes through `writeChoice(setText, values, defaults)` in `sticks/shared.tsx`: when the base sets that key (`useInheritedKeys()` reads `SettingOrigins.base`) it writes the default out; otherwise it removes the line as before. Y (Use Default) still removes the override, which is what restores the inherited value.

Found while testing, not mine: every inherited value shows "Changed here" in the **template/import tests** (reproduces on the baseline tree), and with a connected Steam Controller (2026) the mock saves values as `# @controller type-24 KEY = value` lines (Layout's variant scope), so tests that read the saved text must accept that prefix.

## New hooks other areas can rely on

- `InputSideProxies` renders hidden `button[data-input-command][data-side-proxy]` for inputs that are on the other stick/trigger/pad, or inside a sub-page the front keeps closed. Press-to-find and deep links (`jsm:navigate-input`, Review changes, errors) click them; they switch the rail side or open the sub-page (`reveal` map: touch-stick directions, ring → Dead zone, `LTOUCH` → Touch, wheel slices, "Other controller types"), then focus the real row. Verified for RUP, LRING and TUP (browser, mock pad).
- `data-pad-visual` on the pad picture (the old `.pad-column__well` is gone); `[data-trackpad-page]`, `[data-stick-page]`, `[data-trigger-page]` on the fronts; `[data-stick-fine-tune-row]`, `[data-trigger-fine-tune]`, `[data-trackpad-fine-tune]` on the Fine-tune rows; `[data-group="<id>"]` on a Fine-tune group; `[data-more-item="<id>"]` on the Y menu items.
- The zones drawn on Trackpads (front and Fine-tune ▸ Zones) use `MenuPreview` with `managedFocus`: clickable, but not pad stops, so Down goes from the cards to the rows instead of through the wedges (X steps to the next zone, touching the pad jumps to the zone under the thumb). The jump never fires while a control on the page has focus: a row does not change under the pad.
- `<SettingOrigin>` beside each front heading: `data-setting-origin="RIGHT_STICK_MODE" | "ZL_MODE" | "LEFT_TOUCHPAD_MODE"`.
- Events: `jsm:calibrate-triggers` opens the calibrate flow; `jsm:start-test` starts the Test run (App listens).

## Not done / caveats

- **Calibrate triggers has no progress from the mapper.** `CALIBRATE_TRIGGERS` runs its own steps and reports nothing back, so `TriggerCalibrate` starts the command, then follows it from telemetry (the trigger and the buttons the mapper waits for: D-pad down for the right trigger, Cross for the left; Home abandons), shows what it saw, and offers **Keep these in <config>**, which types `*_TRIGGER_OFFSET/RANGE` into the configuration. The mapper keeps what *it* measured for the controller only until restart (runtime). Exercised against the mock only (a DualSense is not connected here); treat the flow as best-effort until it has run on hardware.
- **Feel it (Resistance)** plays the effect with runtime console commands (`ADAPTIVE_TRIGGER = ON`, `<SIDE>_TRIGGER_EFFECT = …`) and sends the mapper's automatic effect (`<SIDE>_TRIGGER_EFFECT = ON`) when Fine-tune closes, so the runtime does not keep a felt effect; a configuration that sets an effect applies it again the next time it is applied (Apply). Needs a DualSense; hardware check open.
- **Proximity meter** on the grip sheet is a contact bit (telemetry has one bit per grip), so the live meter is on/off, not a graded distance.
- **TriggersEffects** (the spec board) is realised as the nine effect cards plus one row per effect field, not a separate reference sheet.
- **GyroVirtualStick** itself was not refactored; GYRO (P5) already reuses `GameStickMatchGuide` in `gyro/StickSettings.tsx` and has its own `MatchFullTurn`. `sticks/MatchFullTurn.tsx` is the Sticks copy (it writes the same two keys).
- **The grid shortcut path** (Layout's callout → Trackpads ▸ Zones) was checked through the `jsm:navigate-input` proxies, not through Layout's own button.
- **`LRING` reveal** opens Dead zone & edge; the first setting there may take focus before the ring row does.
- **Wheel card with no menu** opens the menu chooser (`StickMenuCard`), rendered only while choosing; picking *Picking from a wheel* in a configuration with virtual menus is covered by `stick_virtual_menus_browser_regression`.
- Tests that still fail, and why, are in the results list above: they fail on things outside P4 (the profile chip / firmware modal, the template inheritance display, the `11 px` text size in On-screen menus, `.mapping-plate` in `pad_navigation`).
