# JSM Evolved — Steam Input parity audit

Working engineering audit started 1 October 2026. **The whole parity pass is in progress.** COMPLETE describes a verified implementation, never a raw-text escape hatch. Physical validation is tracked separately.

## Baseline and architecture

Baseline: `main`, parent HEAD `3d60f86`, mapper HEAD `9991827`; frontend version 0.7.105. Both trees contain substantial existing uncommitted work (UI review, sound library, firmware customisation, native appearance persistence). Preserve it; do not sweep it into a milestone commit. Baseline production web build and comment, modeshift, layer and multi-command regressions pass.

React edits ordinary JSM configuration text. `useKeymapConfig` / sensitivity and touchpad hooks read import-resolved values; the app's layer-aware setters create overrides. `configSerializer` owns saved ordering and unknown lines. `keymap.ts` and `bindingCommands.ts` translate activators. `SettingOrigins`, `SummaryRow`, `NumberField`, `Sheet` and controller-navigation events are shared interaction primitives. Changes should extend these paths.

JSM's `main.cpp` registers typed `JSMAssignment`, specialised aliases and `JSMMacro` commands in `CmdRegistry`. `SettingsManager` owns variables; `JSMSetting` supports chorded setting overrides while `JSMVariable` is global. Binding assignments are generated from physical `ButtonID` values and 25-cell pad/stick menu families. `Mapping.cpp` and `DigitalButton.cpp` own event/action semantics. `JoyShock.cpp` owns stick/gyro processing; `SDLWrapper.cpp` owns hardware acquisition. React must not become a second input engine.

`scripts/audit-jsm-settings.py` walks balanced registration constructors, resolves variable types/defaults and specialised aliases, extracts uppercase, mixed-case and inline enums from all native headers, retains their source paths, and records dynamic binding registration sites. It fails on unresolved command expressions. `docs/jsm-backend-inventory.json` is generated evidence; text references are **candidates**, not graphical coverage. `docs/jsm-setting-ui-coverage.md` records declared handling and remaining work. `scripts/audit-jsm-bindings.py` additionally extracts platform key parsers and native event/action enums and verifies all 174 graphical output tokens using the actual Windows KeyCode/Mapping parser. [jsm-binding-ui-coverage.md](jsm-binding-ui-coverage.md) distinguishes output aliases, parameterized families and remaining activator semantics.

`scripts/audit-jsm-inputs.py` generates the graphical input validator from the actual native ButtonID enum, including aliases, derived inputs and cell bounds. Released menu activation conditions now have a matching control; unknown inputs and future catalogs remain preserved without graphical rewriting. The native catalog independently rejects the SIZE sentinel and invalid inverted cell conditions.

[jsm-enum-ui-coverage.md](jsm-enum-ui-coverage.md) adds reviewed intent for all **39 discovered native enums**, including **167 user-facing values/sentinels**. Its regression fails on an added/removed native enum or value without a declared handling/editor decision. It documents the internally synthesized `RESISTANCE_RAW` trigger envelope and the unverified `NOISE`/`SCRIPT` firmware effects explicitly; enum declarations do not establish runtime parity.

## Current implementation evidence and remaining gaps

The registration contract currently covers **274 commands**, **240 variables**, and **five dynamic mapping families**. Its classifications are COMPLETE 11, PARTIAL 244, INTERNAL 16 and LEGACY 3. Zero unclassified/MISSING declarations means every registered command has an owner or explicit rationale; it does **not** mean 244 partial commands have met the product-quality definition of done. The raw editor is excluded as coverage evidence.

Current implementation uses native settings and native runtime extensions. Cycle is a quoted binding (`"CYCLE 1 | 2 | 3"`); multi-input activation is ordinary assignment syntax (`GYRO_ON = ALL MISC5 !MISC6`). Existing single-input syntax remains valid. New output telemetry reports only successfully submitted virtual-controller vectors; older installed mappers show its absence rather than synthetic runtime output.

Fresh Valve guides established additional concrete gaps: relative pad mouse-to-joystick velocity mapping is different from positional stick passthrough, and directional swipe requires its own gesture semantics. These remain outstanding engineering work. Gyro angular feedback now has a separate native implementation and graphical controls rather than sharing pad movement ticks. Named-menu ownership and remembered hotbar navigation also have native implementations and focused tests; their remaining verification is explicit in the matrix.

The named-menu format and runtime design are documented in [named-virtual-menus.md](named-virtual-menus.md). Menus use the actual native Mapping/DigitalButton engine, including optional centre actions, Cycle, haptic/command bindings and event modifiers. The native parser replaces catalogs transactionally and retains the previous catalog on error. Unsupported future catalogs remain untouched by the GUI. Unknown presentation fields, quoted `#` content and Unicode survive graphical edits. Gamepad dependencies and Xbox/DS4 conversion include ordinary and centre menu actions. Menu output labels now describe bindings in words and keep source syntax in tooltips; centre-size values use readable percentages.

Gyro setting chords now move their existing tuning and comments when the activation input changes. Copy/paste and dirty-setting inventory include virtual correction, trackball and motion settings. Calibration reads the last COUNTER/IGNORE mouse-speed command and writes an explicit reset when disabling inherited compensation.

Automated, simulated telemetry and physical tests must remain separate. No physical controller operation has been claimed. The earlier snapshot found a mapper and Steam running. Windows PnP detected the Valve 28DE:1304 puck; that is not proof of a live paired controller. The installed elevated app owned UDP telemetry port 8974 in that snapshot. The running mapper has not been replaced and its telemetry listener has not been displaced. No Sony device was detected in the earlier PnP snapshot. Mock-browser device states are simulated.

- Build: TypeScript, production web, Rust, C++ and existing node/browser/Python regressions.
- Steam Controller: independently touch/click both pads, stick touch, both grips, all four rear buttons, gyro drift/calibration/slow aim/fast turns, analogue trigger stages, game-visible virtual output, per-actuator haptics, configurator navigation.
- DualSense: gyro, touchpad, DS4 touch/motion, trigger stages/calibration/effects and output dependencies.
- Controller-only game: enable virtual output, bind every game action to gamepad output, hide physical duplicates using the existing visibility workflow, tune a 20% deadzone/nonlinear curve/high sensitivity, verify no mouse/keyboard events and compare slow/fast aiming.
